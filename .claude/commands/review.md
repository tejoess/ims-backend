allowed-tools: Read, Bash, Grep, Glob, Task

Precondition: phase is `EVIDENCE`. If verification has not passed, say so and stop.

Run the `pr-reviewer` agent. Present ONE consolidated package:

- `evidence.md` — AC→TC coverage table and per-layer results, generated by
  `collect-evidence.sh` from raw runner output, with `red.log` alongside it
- `diff.patch` — the full change
- The reviewer agent's own risk and blast-radius findings
- **Migration verification** — the up and down results from `evidence.md`, the
  DDL diff, and confirmation that the down migration restored the prior schema.
  If the plan flagged the migration as lossy, restate that here: the human is
  approving that loss, and it should not be something they have to remember
  from Gate 1.
- Assumptions from `plan.md` that are still unconfirmed
- The draft PR description

Then stop and wait. Gate 2 has **three** outcomes — route them differently:

| The human says | Goes to | Because |
|---|---|---|
| approve | `/create-pr` | done |
| it is broken | back to step 5 of `/implement` | the plan was right, the code is not |
| wrong scope | back to `/plan` | the plan itself was wrong — re-plan, do not patch |
| abandon | `/abandon` | reset to the checkpoint |

Routing a scope disagreement into the fix loop is the failure this table exists
to prevent. If the feedback is about *what* was built rather than *whether it
works*, it is a re-plan.
